# IT学習アプリ 仕様書(Claude Code 向け)

作成日:2026-10-27
対象:このリポジトリで実装を担当する Claude Code

---

## 0. このアプリの目的

利用者は、Claude のチャットで IT の分からないことを質問し、理解してきました。このアプリは、その**理解した知識を忘れないため**の、自分専用の学習ツールです。

**2026-11-08 方向性の変更**:主役は「**チャットで教えてもらった解説を、チャットを遡らずに教科書のように読み返すこと**」。問題は、読んだ後の確認用の付録という位置づけにする。

- **主役**:目次から引ける読み物(たとえ・要約・図・解説・チャットでのやりとり)
- **付録**:確認問題・演習・復習(基本情報技術者試験の対策としても使う)
- **その後**:合格後も、IT の自分専用の参考書として使い続ける
- **継続的に育てる**:新しいチャットのセッションを、定期的に教材として追加していく
- **使う場面**:主にスマホの隙間時間。PC でもじっくり使える

利用者のつまずき方の分析は `docs/analysis.md` にあります。**機能の多くはこの分析が根拠なので、実装前に必ず読んでください。**

## 1. 全体構成

```
.
├── CLAUDE.md                 … Claude Code 用のルール
├── content/
│   ├── packs/*.json          … 教材データ(チャット側で作成。アプリはこれを読むだけ)
│   ├── SCHEMA.md             … 教材データの形式
│   └── topic-index.md        … トピック一覧(自動生成。新セッション追加時にチャットへ渡す)
├── docs/
│   ├── SPEC.md               … この仕様書
│   ├── analysis.md           … つまずき分析
│   └── ADDING_CONTENT.md     … 新しいセッションを追加する手順
├── tools/
│   ├── content-lib.mjs       … パックの統合ロジック(アプリ側は TS に移植)
│   └── validate.mjs          … 教材データの検査
└── app/ (または src/)        … アプリ本体(これから実装)
```

**役割分担**
- 教材データ(`content/packs/`)は、Claude のチャット側で作って追加します。Claude Code は教材の中身を書き換えません(明らかな誤字・形式エラーの修正を除く。修正したら利用者に伝える)。
- アプリは、ビルド時に `content/packs/*.json` を読み込み、統合して表示します。**パックを足すだけでアプリに反映される**ことが最重要の要件です。

## 2. 技術スタック(推奨)

| 項目 | 推奨 | 理由 |
|---|---|---|
| ビルド | Vite | 静的サイトとして書き出せる |
| UI | React + TypeScript | 状態の多い学習 UI に向く |
| ルーティング | HashRouter(react-router) | GitHub Pages でもリロードで 404 にならない |
| Markdown 表示 | react-markdown + remark-gfm | 教材の解説は Markdown(表あり) |
| 図 | mermaid(使う画面でだけ遅延読み込み) | トピックの `diagram` |
| オフライン・ホーム画面追加 | vite-plugin-pwa | スマホでアプリのように使う |
| 学習記録の保存 | IndexedDB(idb-keyval など)。小さい設定は localStorage | サーバ不要 |
| テスト | Vitest(統合ロジック・復習間隔の計算) | |
| 公開 | GitHub Pages(GitHub Actions で自動デプロイ) | 無料 |

**サーバは使いません。** 学習記録は端末のブラウザに保存します(PC とスマホの記録の受け渡しは 6章)。

**公開について(決定済み)**:公開リポジトリ+GitHub Pages(2026-10-28 決定、2026-11-08 再確認)。教材(つまずき・チャットの原文を含む)は誰でも見られるので、**個人情報は入れない**。資料に利用者の名前は書かない。パックを追加するときは個人情報の確認をしてから追加する(CLAUDE.md の手順、`docs/ADDING_CONTENT.md`)。

## 3. 教材データの読み込み

1. `import.meta.glob('/content/packs/*.json', { eager: true })` などで、全パックをビルド時に読み込む
2. **ファイル名順**に並べて、`tools/content-lib.mjs` の `mergePacks` と同じルールで統合する
   - トピックは `id` で統合。後のパックの配列フィールドは追記(重複除外)、スカラーフィールドは上書き
   - 比較カード・記号・ガイドは `id` で後勝ち
3. 統合ロジックは TypeScript に移植し、Vitest で `content-lib.mjs` と同じ結果になることをテストする
4. `npm run build` の前に `node tools/validate.mjs` を実行し、エラーならビルドを止める(`prebuild` スクリプト)

## 4. 画面と機能

優先度:**P0** = 試験対策に必須(最初に作る)、**P1** = 早めに欲しい、**P2** = 余裕があれば

画面下のタブ:**ホーム/セッション/検索/しおり/演習**(2026-11-08)

### 4.1 ホーム(P0)
- **続きから読む**:最後に開いたトピック
- **最近追加されたセッション**:パックに入った日の新しい順に3件
- **目次**(主役。4.2)
- 今日の復習・弱点表示・試験日までの日数は、**演習タブ**に置く(4.4、4.5、4.8)
- 初回起動時は、`missedInSession: true` の問題(セッションで間違えた問題)を「今日の復習」に入れておく

### 4.2 目次(P0)
- 分野(`field`)→ 大分類(`category`)→ トピックの3階層。スマホはアコーディオン
- 既読のトピックに ✓、しおりに ★ を表示。大分類ごとに「既読数/トピック数」
- 習熟度の色分け(未学習/学習中/定着)は、記録の保存を作るときに追加する
- PC:左に目次、右に本文の2カラム(P1)

### 4.3 トピック画面(P0)
読み物が主役。上から次の順で表示します。

1. タイトル、分野・大分類、出典セッション(セッション画面へのリンク)、**しおり(☆)**
2. **このページの目次**(見出しを押すとその場所へ移動。やりとりは見出しごとに)
3. **たとえ**(`analogy`)
4. **要約**(`summary`)と**要点**(`keyPoints`)
5. **図**(`diagram`。mermaid)
6. **解説**(`explanation`)と**公式**(`formulas`)
7. **チャットでのやりとり**(`dialogues`)。チャット風に、質問は短く右寄せ、解説は全幅で主役にする。dialogues がなければ出さない
8. **あなたのつまずき**(`pitfalls`)。目立つ色で「前回ここで止まりました」
9. **用語**(`terms`)
10. **関連トピック**:前提トピック(`prerequisites`)、関連トピック(`related`)、似た概念との比較カード
11. **確認問題**(折りたたみ。開くとその場で解ける)
12. 「読み終えた」ボタン(既読にする)

読みやすさ:本文は 17px 程度、行間を広く。解説の中の見出しはページの見出しより小さくする。

### 4.4 演習(P0)
- 1問1画面。選択肢は親指で押せる大きさ
- 出題モード:今日の復習/トピック別/分野別/弱点集中/つまずきタグ別(P1)/ランダム
- **「問題文を言い換える」ボタン**:`readingAid` があれば表示(分析①への対策)
- **問題文中の用語をタップすると用語集を表示**(P1):全トピックの `terms` の `term` と一致する語をリンク化
- 回答前に**確信度**を選べる(「自信あり」「たぶん」)。復習間隔の計算に使う
- 数値問題(`numeric`)は数字キーボードで入力。`tolerance` 以内なら正解
- **回答後の表示**
  - 正誤
  - 選んだ誤答に `wrongReasons` があれば、最初に大きく表示(「この選択肢を選んだなら、こう考えたのでは?」)
  - 解説(`explanation`)
  - 不正解のとき、トピックの**前提トピック**へのリンクを「ここに戻ると解きやすくなります」と表示(分析③)
  - 「トピックを読む」「次の問題」

### 4.5 復習(間隔反復)(P0)
問題ごとに次の状態を保存します。

```ts
type QuestionState = {
  box: number;            // 0〜5
  due: string;            // 次の復習日(YYYY-MM-DD)
  attempts: number;
  correct: number;
  lastAnsweredAt?: string;
  lastChoice?: string;    // 直近の回答
  history: { at: string; correct: boolean; confident: boolean; choice?: string }[];
};
```

- 間隔(日):box 0 = 当日、1 = 1日、2 = 3日、3 = 7日、4 = 14日、5 = 30日
- 正解かつ「自信あり」→ box + 1
- 正解だが「たぶん」→ box はそのまま(次の復習日は今の box の間隔で再設定)
- 不正解 → box = 0(当日中にもう一度出す)
- 未回答の問題は「未学習」。`missedInSession: true` は初回から box 0・当日扱い
- 教材パックに問題が追加されても、既存の記録は消さない(問題 id で紐づけ)

### 4.6 比較カード(P0)
- `comparisons` を一覧表示。カードを開くと `oneLiner`(違いの一言)と比較表
- トピック画面から、関係する比較カードへリンク
- 分析⑤「似た概念の混同」への対策なので、スマホで表が横にはみ出さない表示にする(横スクロールは表の中だけ)

### 4.7 記号辞典(P1)
- `symbols` を一覧表示。トピック画面・演習画面から関連する記号へリンク
- 分析②「記号・図の読み方」への対策

### 4.8 記録・弱点分析(P0)
- 分野別・大分類別の正答率と回答数
- **つまずきタグ別のミス数**(`stumbleTags`。タグの日本語名は `content-lib.mjs` の `STUMBLE_TAGS`)
- 弱点スコア(大分類ごと):直近の回答を重視した誤答率。例:直近20回答の誤答率 × 0.7 + 全期間の誤答率 × 0.3。回答が少ない大分類は `docs/analysis.md` 3章の初期値(★の数)を使ってよい
- 学習した日のカレンダー(P2)

### 4.9 用語集(P1)
- 全トピックの `terms` を五十音・アルファベット順で検索できる一覧
- 用語からトピックへ戻れる
- フラッシュカード表示(表:用語、裏:説明)(P2)

### 4.10 自分の言葉で説明する(P1)
分析4章「自分の言葉で要約して確かめる」学び方を機能にしたものです。
1. トピックを選ぶと、タイトルだけが表示される
2. 利用者がテキスト欄に、自分の言葉で説明を書く
3. 「答え合わせ」で `summary` と `keyPoints` を表示
4. 自己採点(できた/半分/できなかった)を記録。書いた説明も保存して、後で読み返せる

### 4.11 問題文の読み方ガイド(P1)
- `guides` を表示。演習画面の「問題文を言い換える」の近くからも開ける

### 4.12 設定(P0)
- 試験日(P1)
- 学習記録の書き出し/読み込み(6章)
- 記録のリセット(確認ダイアログつき)
- ダークモード(端末の設定に従う+手動切替)

---

### 4.13 セッション画面(P0)
- 一覧:セッション(チャット)を日付の新しい順に。日付・トピック数・やりとり数
- 詳細:元のチャットへのリンク、このセッションのトピック(折りたたみ)、やりとりを日付の古い順に。各やりとりからトピックへ戻れる

### 4.14 全文検索(P0)
- トピック名・たとえ・要約・解説・やりとり・つまずき・用語を検索する
- 全角・半角、大文字・小文字を区別しない。空白で区切るとすべての語を含むもの
- 結果はトピックごとに、どこで一致したかと前後の文を表示。押すとその場所へ移動する

### 4.15 しおり・既読(P0)
- トピック画面の ☆ でしおり、「読み終えた」で既読。しおりタブで一覧
- 端末(localStorage)に保存し、トピック id で紐づける。書き出し/読み込み(6章)の対象に含める

## 5. UI の方針

- **スマホ優先**:幅 360px で崩れない。1問1画面、主なボタンは画面下部(親指の届く範囲)
- **PC**:幅 1024px 以上でマップ+本文の2カラム
- 文字は日本語。用語は教材データの表記に合わせる
- 正解/不正解は色だけでなく、記号や文字でも分かるようにする
- 教材の Markdown の表は、スマホでは表の中だけ横スクロール

---

## 6. PC とスマホの記録の受け渡し

学習記録はブラウザごとに保存されるので、PC とスマホで別々になります。

- **P0**:設定画面で「記録を書き出す」(JSON ファイルをダウンロード)と「記録を読み込む」(ファイル選択)。読み込み時は、問題ごとに `lastAnsweredAt` が新しい方を採用して統合する
- **P2**:自動同期。外部サービス(GitHub Gist、Supabase など)が必要で、認証情報の扱いも絡むため、**利用者と相談してから**実装する

---

## 7. 実装の進め方(推奨順)

2026-11-08 に方向性を変更したため、順番を組み替えました。

1. ✓ プロジェクト作成、教材の読み込みと統合(TS 移植+テスト)、`prebuild` で検査
2. ✓ 演習画面(選択・数値、言い換え、誤答理由、解説)、GitHub Pages への自動デプロイ
3. ✓ 読み物中心への作り替え:目次ホーム、トピック画面、dialogues、セッション画面、全文検索、しおり・既読
4. 復習(間隔反復)、演習タブの「今日の復習」、記録・弱点分析
5. PWA 化(オフラインで読める)
6. 書き出し/読み込み(しおり・既読を含む)
7. P1 の機能(PC の2カラム、比較カード一覧、記号辞典、用語集と用語リンク、自分の言葉で説明、ガイド、試験日)
8. P2

各段階で、利用者がスマホで触れる状態にして見せ、意見を聞きながら進めてください。

## 8. 受け入れ条件

- [ ] `content/packs/` に新しい JSON を1つ追加し、push するだけで、アプリに新しいトピックと問題が出る
- [ ] 既存トピックと同じ id のトピックを含むパックを追加すると、そのトピックに問題・つまずきが追記される(重複しない)
- [ ] パックを追加しても、既存の学習記録が消えない
- [ ] 検査エラーのあるパックではビルドが止まり、エラー内容が分かる
- [ ] スマホ(幅 360px)で、ホーム → 今日の復習 → 回答 → 解説 → 次の問題 が片手で操作できる
- [ ] 誤答したとき、その選択肢の `wrongReasons` と前提トピックへのリンクが出る
- [ ] オフラインでも演習できる(PWA)
- [ ] 記録を書き出して別の端末で読み込める
- [ ] dialogues を含むパックを追加すると、トピック画面とセッション画面にやりとりが出る(同じ sourceKey + title は重複しない)
- [ ] 全文検索で、やりとりの中の言葉も見つかり、その場所へ移動できる
- [ ] しおり・既読が、再読み込みやパックの追加で消えない

## 9. やらないこと

- ログイン機能、サーバ、データベース(P2 の同期を利用者と合意するまで)
- 教材の自動生成(教材はチャット側で作る)
- 教材の中身の書き換え(形式エラーの修正を除く)
